## 2. 担当をまたぐ受け渡し（ここだけ守れば合流できる）

自分のファイルの中身は自由に書いて構いません。守るのは次の3点だけです。

### 2.1 DBに触るのは `db.py` 経由だけ

ナカムラさんとオオイシさんはSQLを書きません。アベさんの関数を呼びます。

```python
db.save_day(user_id, date, {"sleep": 420, "school": 300, ...})   # 保存（ナカムラ）
db.fetch_records(user_id, "2026-10-13", "2026-10-19")            # 取り出し（オオイシ）
```

テーブルの構造を知らなくても作業できる状態にします。これが一番重要な分離点です。

### 2.2 カテゴリ名と利用者IDは `categories.py` から取る

自分のファイルに `"睡眠"` や `"sleep"` と直接書かないでください。表記が1文字ずれるだけでデータが分裂します。

```python
import categories
categories.CATEGORIES   # [("sleep", "睡眠"), ...] 入力画面に並べる順
categories.LABELS       # {"sleep": "睡眠", ...} キー -> 表示名
```

### 2.3 グラフは「オオイシが作り、ナカムラが貼る」

```python
name = graph.make_pie(user_id, date_from, date_to)   # ファイル名を返す
```

`app.py` はこの戻り値を `list.html` に渡すだけです。画像を作りません。

## 3. 着手の順番

アベさんの `db.py` が他2人の前提になります。

**中身は空（`pass`）で構わないので、関数名・引数・戻り値だけ先に決めてpushしてください。**
それが入った時点で、残り3人は各自のファイルだけを見て同時に進められます。

オカダは並行してEC2側を準備します。

`main` に直接pushしないでください（`docs/03` の8章）。

## 5. 注意点

- **`app.db` / `.env` / `static/graphs/` の中身はGitに入りません**（`.gitignore` 済み）。入れてしまうと、`app.db` は各自の記録が混ざって毎回衝突し、`.env` はDiscordのトークンが公開リポジトリに残り、グラフ画像は毎日差分が出ます。
- **日本語を読み書きするときは `encoding="utf-8"` を明示**。Windowsでは省略するとcp932になり、文字化けや例外の原因になります。
- **グラフ画像のファイル名は毎回変える**。同じ名前だとブラウザが古い画像をキャッシュし、「更新したのに前のグラフが出る」という症状になります。
- **合計時間の検証はサーバー側（Python）で行う**。JavaScriptを使わない方針のため、入力中に画面で合計が自動更新されることはありません。保存ボタンを押した後にサーバーが判定します。
- **`requirements.txt` にライブラリを足したいときは先に相談**。黙って足すと、他の3人の手元で `ModuleNotFoundError` が出ます。
- **AIが「`app.py` をこう書き換えて」と言ってきても、担当外なら従わない**（`docs/02` 4章ルール3）。ここが一番崩れやすいポイントです。
